# [!DNL Observation for Adobe Commerce] ナードレットの使用方法

## 論点の検証に関する一般的考え方

環境リソースの状態を確認します。

* **[!UICONTROL Storage Free and MySQL % free storage by node]** フレームの%を確認してください。

  * ストレージが少ない場合は、フレームのヘッダーのリンクに従ってください。

* **[!UICONTROL free system memory and Swap memory free in bytes]** フレームの%を確認してください。

  * メモリが非常に少ない状態が表示される場合は、問題の原因になる可能性があります。

* **[!UICONTROL Alerts during the timeframe]** フレームを調べます。

  * Adobe Commerce クラウド版インフラストラクチャは[!DNL Managed alerts]を提供します。 ヘッダーのリンクをクリックすると、特定のアラートに対するユーザーの行動を決定するのに役立つ[!DNL Support Knowledge Base]件の記事を確認できます。

* **[!UICONTROL CPU % by host]** フレームを調べます。CPU使用率が高い場合は、フレームのヘッダーの[!DNL Support Knowledge Base]の記事を確認してください。 また、トラフィックのピーク時に、データベースのインポート/エクスポートまたはバックアップが実行されていないことを確認します。

* **[!UICONTROL Web Traffic volume compared to one week ago]** フレームを確認する：同じ期間にトラフィックが前週よりもはるかに多い場合は、説明できますか（たとえば、販売キャンペーンや販売された新製品など）?
  * トラフィックの増加を説明できない場合は、実稼動環境の平均応答時間（ミリ秒）を確認します。 応答時間に寄与するトラフィックの増加は、通常のトラフィックとは異なりますか？ タイムフレームを展開して、異常かどうかを確認します。
  * トラフィックの増加は、web トランザクションに影響を与えていますか？ エラーがないか&#x200B;**[!UICONTROL Response Code]** フレームを確認してください。 サイトがダウンしている場合は、フレームヘッダーの`Site Down?` リンクをクリックできます。 フレームは、発生しているエラーとその頻度を識別します。
  * 誰かがweb サイトに変更をデプロイしましたか？ **[!UICONTROL Deployment Log Entries]** フレームは、問題の期間にデプロイが行われたかどうかを示します。 デプロイメント直後に問題が発生した場合は、デプロイメントアクティビティによってサイトに追加の負荷が追加されている可能性があります（キャッシュがクリアされる、サービスが再起動されるなど）。
  * アップサイズまたはダウンサイズが発生しましたか？ サイトのサイズが一時的に変更された場合は、元のクラスターサイズに戻っている可能性があります。 サイトの容量を増やすようにリクエストした場合、アップサイズが発生する可能性があります。 **[!UICONTROL Upsize/Downsize – vCPU view over the timeline]** フレームを確認してください。 このフレームは、1つの特定のノードで停止を検出することがあります。 サイズが減少した場合は、1つ以上のノードに問題があることを示している可能性があります。

* 「**[!UICONTROL IP Frequency]**」タブは、オリジンサーバーに対して作成されたIP アドレスからのリクエスト頻度を識別します（つまり、[!DNL Fastly]からリクエストがキャッシュされなかった74として提供できなかったことを意味します）。

  * [!DNL Fastly]関連の問題については、**[!UICONTROL Fastly Cache]** フレームを確認し、エラーファセットを選択して、エラーであるリクエストの割合を確認します。 web以外の読み込みと一致する場合は、バックエンドの問題を示している可能性があります。
  * 読み込みがweb トラフィックによるものではないように見える場合は、エラーまたは非web リクエストのビルドアップ（低速クエリや[!DNL crons]など）が発生している可能性があります。

* 問題/問題のタイムラインと一致する可能性のあるエラーについては、**[!UICONTROL Database Errors]** フレームを確認してください。
* **[!UICONTROL Database mysql-slow.log]** フレームをチェックして、発生しているSQL ステートメントを特定します。 クエリが最適化されていない場合、`INSERT`、`UPDATE`、`DELETE`のコマンドに時間がかかる場合があります。 大きなテーブルに対して行う場合、`SELECT` ステートメントでも非常に非効率的になる可能性があります。
* **[!UICONTROL PHP States]**&#x200B;と&#x200B;**[!UICONTROL PHP Errors]** フレームには、PHPに関する潜在的な問題が表示されます。 **[!UICONTROL PHP States]** フレームには、PHP プロセスの終了、開始、およびサービスがノードごとに準備状態に達したときに表示されます。 **[!UICONTROL PHP Errors]** フレームは、メモリ サイズ、ワーカー、サーバー数など、PHPの問題が発生している場所を特定するのに役立つ可能性があります。
* トランザクションの待ち時間を確認するには、トランザクション – 平均時間、最大時間、最小テーブルを列で並べ替えて、最も長い実行中のトランザクション期間を表示できます。 オーバーロードされたクラスターには、トランザクションの潜在的な期間がありますが、メソッドまたは[!DNL cron]に関する問題を特定する可能性のある異常も表示されます。
* **[!UICONTROL Cron error]** フレームには、[!DNL cron]個のロック、[!DNL cron]個のログに関連付けられている可能性のあるSQL エラー、および専用ステージング環境がある場合に実稼動環境で実行されている可能性のある共有ステージング [!DNL crons]が表示されます。
* [!UICONTROL ElasticSearch Errors] フレームには、[!DNL Elasticsearch] クエリ、データ、またはインデックスに関する大きな問題を示す可能性のあるエラーが表示されます。
