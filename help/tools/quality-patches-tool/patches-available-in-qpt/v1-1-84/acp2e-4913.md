# ACP2E-4913: データベースのデッドロック後にREST APIの出荷と請求書の作成が再試行されない

ACP2E-4913 パッチは、操作が再試行されないためにデータベースのデッドロックが発生した場合に、REST APIを介して出荷または請求書を作成する際に永続的に失敗する問題を修正します。 このパッチは、[[!DNL Quality Patches Tool (QPT)]](/help/tools/quality-patches-tool/quality-patches-tool-to-self-serve-quality-patches.md) 1.1.84がインストールされている場合に利用できます。 パッチ IDはACP2E-4913です。 この問題は、Adobe Commerce 2.4.10で修正される予定です。

## 影響を受ける製品とバージョン

**パッチはAdobe Commerceのバージョン**&#x200B;用に作成されました

* Adobe Commerce（すべてのデプロイメント方法） 2.4.8-p3

**Adobe Commerceのバージョンとの互換性：**

* Adobe Commerce（すべてのデプロイメント方法） 2.4.7 - 2.4.8-p5

>[!NOTE]
>
>このパッチは、新しい[!DNL Quality Patches Tool] リリースを含む他のバージョンに適用される可能性があります。 パッチがAdobe Commerceのバージョンと互換性があるかどうかを確認するには、`magento/quality-patches` パッケージを最新バージョンに更新し、[[!DNL Quality Patches Tool]：パッチの検索ページ &#x200B;](https://experienceleague.adobe.com/tools/commerce-quality-patches/index.html)で互換性を確認します。 パッチ IDを検索キーワードとして使用して、パッチを検索します。

## イシュー

操作が再試行されないため、データベースのデッドロックが発生すると、REST APIを介した出荷または請求書の作成が永続的に失敗します。

<u>複製する手順</u>:

1. 発送可能な複数の注文と、請求書を作成できる複数の注文を準備します。
1. 統合が読み込み中になる可能性があるため、これらの注文に対して複数の`POST /rest/V1/order/<orderId>/ship` リクエストを並行して送信します。
1. 同じ方法で、複数の`POST /rest/V1/order/<orderId>/invoice` リクエストを並行して送信します。
1. APIの応答と`var/log/exception.log`を確認してください。

<u>期待される結果</u>:

デッドロックの後、操作が再試行され、出荷または請求書が作成されます。

<u>実際の結果</u>:

一部のリクエストは、次のデッドロックエラーで失敗します。 出荷または請求書は作成されないので、手動で作成する必要があります。

```
SQLSTATE[40001]: Serialization failure: 1213 Deadlock found when trying to get lock; try restarting transaction
```
