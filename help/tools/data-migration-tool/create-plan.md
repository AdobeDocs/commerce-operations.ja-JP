# データ移行計画の作成

移行を成功させ、問題を回避するには、移行を徹底的に計画し、テストする必要があります。

## 始める前に：アップグレードを検討してください

移行は、大幅な変更をおこない、サイトを次のレベルの成長に備えるのに適したタイミングです。 新しいサイトを追加のハードウェアで設計する必要があるか、より高度なトポロジでより優れたキャッシュ階層を使用する必要があるかを検討します。

## 手順1：現在のサイトの拡張機能を確認する

* どの拡張機能をインストールしましたか？

* 新しいサイトにこれらすべての拡張機能が必要かどうかを確認しましたか？ 安全に取り外すことができる古いものがあるかもしれません。

* 拡張機能のMagento 2 バージョンが存在するかどうかを判断しましたか？ [Commerce Marketplace](https://commercemarketplace.adobe.com/)にアクセスして、最新バージョンを確認するか、拡張機能プロバイダーにお問い合わせください。

* 拡張機能からどのようなデータベースアセットを移行しますか？

## ステップ 2：移行に向けてストアを構築して準備する

* 少なくとも既存のMagento 1 システムと一致するトポロジとデザインを使用して、Magento 2 ハードウェアシステムをセットアップします

* Magento 2 （このリリースのすべてのモジュール）と[!DNL Data Migration Tool]を[ システム要件](../../installation/system-requirements.md)を満たすシステムにインストールします

* [!DNL Data Migration Tool] コードをカスタマイズして、特定のデータ（CMS ページ、営業規則など）をスキップしたり、移行中にカスタマイズを変換したりできます。 移行の仕組みについて詳しくは、[!DNL Data Migration Tool]の[技術仕様](technical-specification.md)を参照してください

## ステップ 3：ドライ作動

実稼動環境で移行を開始する前に、テスト環境のすべての移行手順を実行します。

このような移行テストでは、次の手順に従います。

* Magento 1 ストアをステージングサーバーにコピーする

* レプリケートされたMagento 1 ストアをMagento 2に完全に移行する

* 新しいストアを徹底的にテストする

## 手順4：移行を開始する

1. [!DNL Data Migration Tool]がMagento 1およびMagento 2 データベースに接続するためのネットワーク アクセス権を持っていることを確認してください。 ファイアウォール内の対応するポートを開きます。

1. Magento 1の管理パネル（Order Managementを除く）で、発送、請求書の作成、クレジットメモの作成など、すべてのアクティビティを停止します。 許可されているアクティビティのリストは、[!DNL Data Migration Tool]でデルタ モードの設定を調整することで拡張できます。

   >[!NOTE]
   >
   >Magento 2 ストアが公開されるまで、これらのアクティビティを再開しないでください。

1. すべてのMagento 1 cron ジョブを停止することをお勧めします。

   移行中に一部のジョブを実行する必要がある場合は、デルタ モードで処理できない方法でデータベース エンティティを作成または変更しないようにします。

   例えば、`enterprise_salesarchive_archive_orders` cron ジョブは、古い注文をアーカイブに移動します。 デルタモードがこのジョブを認識し、アーカイブされた注文を適切に処理するため、移行中にこのジョブを実行しても安全です。

1. [!DNL Data Migration Tool]を使用して、設定とweb サイトを移行します。

1. Magento 1 メディアファイルをMagento 2にコピーします。

   これらのファイルを`magento1-root/media` ディレクトリから`magento2-root/pub/media`に手動でコピーします。

1. [!DNL Data Migration Tool]を使用して、Magento 1 データベースからMagento 2 データベースにデータを一括コピーします。

   一部の拡張機能に移行するデータがある場合は、Magento 2に対応した拡張機能をインストールする必要がある場合があります。 拡張機能の構造がMagento 2 データベースで異なる場合は、[!DNL Data Migration Tool]で提供されるマッピングファイルを使用します。

1. すべてのMagento 2 インデクサーのインデックスを再作成します。 詳しくは、_設定ガイド_&#x200B;の「[ インデクサーの管理](../../configuration/cli/manage-indexers.md)」を参照してください。

## 手順5：移行されたデータの変更（必要な場合）

場合によっては、移行後に、カタログ構造、セールスルール、CMSのページが異なるMagento 2 ストアを使用したい場合があります。

手動でのデータ変更を行う際には、慎重に対応することが重要です。 エラーは、次の増分データ移行手順で発生します。

例えば、Magento 2から削除された商品：Magento 1の実店舗で購入された商品で、Magento 2の実店舗ではもう入手できません。 このような購入に関するデータを転送すると、差分モードで[!DNL Data Migration Tool]を実行する際にエラーが発生する可能性があります。

## 手順6：増分データの更新

データを移行した後、デルタモードを使用して、Magento 1からの増分更新（新規注文、レビュー、顧客プロファイルの変更など）を取得し、Magento 2に転送します。

* 増分移行を開始します。更新は継続的に実行されます。 `Ctrl+C`を押すことで、いつでも更新の転送を停止できます。

* この期間にMagento 2のサイトをテストし、問題を早期に発見します。 問題が発生した場合は、`Ctrl+C`を押して増分移行を停止し、問題を解決した後に再度開始します。

>[!NOTE]
>
>Magento 2 サイトのテストを行い、移行プロセスを同時に実行すると、ボリュームチェックの警告が表示される場合があります。 Magento 2では、Magento 1 インスタンスに存在しないエンティティを作成するため、この問題が発生します。

## ステップ 7：本番稼動

Magento 2 サイトが完全に移行され、正常に機能したら、カットオーバーを完了します。

1. Magento 1 システムをメンテナンスモードにします（ダウンタイム開始）。

1. 移行ツールコマンドウィンドウでControl + C キーを押して、増分更新を停止します。

1. Magento 2 cronのジョブを開始します。

1. Magento 2 システムで、ストックインデクサーを再インデックスします。 詳しくは、_設定ガイド_&#x200B;の「[ インデクサーの管理](../../configuration/cli/manage-indexers.md)」を参照してください。

1. 好みのツールを使用して、Magento 2 システムでページをヒットすることで、ストアフロントを使用する顧客よりも先にページをキャッシュできます。

1. Magento 2 サイトの最終的な検証を行います。

1. DNSやロードバランサーなどを変更して、新しい実稼動ハードウェアを指定します（ダウンタイム終了）。

1. Magento 2 ストアが利用可能になりました。 すべてのアクティビティを再開できます。
