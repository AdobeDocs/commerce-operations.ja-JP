# Adobe Commerceのハイライト（v2.4.10）

## v2.4.10-alpha1のハイライト

Adobe Commerce 2.4.10-alpha1 リリースには、次のハイライトが適用されます。

### Braintree

#### Fastlane

より高速で安全なゲストチェックアウト体験を実現するために、Fastlane by PayPal サポートを追加しました。
顧客は、支払いと配送の詳細を保存することをオプトインして、今後の購入を迅速化できます。
Fastlaneのお客様は、1回限りのコードを使用して認証し、保存された情報を取得できます。
また、顧客は、決済時に保存したカードや配送先住所を追加または変更できます。
Fastlaneのスタイル設定と設定オプションもサポートされています。

_バンドル–3521_

#### Braintreeのインサイト

Adobe Braintree Insightsを導入し、加盟店がMagento Adminで一元的な支払いパフォーマンスレポートを入手できるようにしました。
トランザクション、決済、辞退、ゲートウェイ拒否、支払い方法のデータを可視化します。
web サイト、日付範囲、日単位、週単位、月単位でのフィルタリングに対応しています。
レポート用に最大13か月間の過去の取引データをインポートできます。
最大3年間のトランザクションデータを維持するためのデータ保持と自動クリーンアップが含まれています。

_バンドル–3522_

#### Swish – 現地のお支払い方法

Braintree Magento拡張機能で、スウェーデンの新しい現地決済方法としてSwishを導入。
Swishは、必要なスウェーデンの加盟店、国、通貨、支払い設定が満たされた場合に利用できます。
スウェーデンの配送先住所または請求先住所をお持ちのお客様は、チェックアウト時にSwishを使用して支払いを完了できます。
適切なチェックアウト応答による、成功、キャンセル、失敗したSwish支払いフローのサポートを追加しました。
Swishは、必要なすべての設定条件が満たされた場合にのみ表示されます。

_バンドル–3523_

#### バージョンをv4.9.0にアップグレード

Braintree モジュールをv4.8.0からv4.9.0にアップグレードしました。
アップグレードには、最新のBraintree モジュールの変更と機能強化が含まれています。
Braintreeのチェックアウトと決済処理が、アップグレード後も引き続き期待どおりに機能することを確認しました。
アップグレードされたモジュールでは、既存の顧客のチェックアウトおよび注文作成フローが引き続き機能します。
基本的な回帰テストは、アップグレードによって問題が発生していないことを確認するために実行されました

### フレームワーク

#### [2.4.10-alpha1] プラットフォームコンポーネントのアップグレード

Adobe Commerce 2.4.10-alpha1には、プラットフォームの依存関係のアップグレード、互換性の向上、フロントエンドライブラリのアップデート、安定性の修正が含まれています。 このリリースには、次の完了済みの変更が含まれています。

- Predis: `predis/predis`を2.xから3.xにアップグレードし、RedisおよびValkey環境との互換性を改善し、Redis クライアントをサポートされている最新の依存関係バージョンに合わせました。
- Magento Composer インストーラー：インストールプロセスを完了せずに`magento-composer-installer`が無言で終了する問題を修正し、Composer ベースのインストールの信頼性を向上しました。
- Knockout.js：必要な検証と互換性の更新に加えて、Knockout.jsを3.5.1から3.5.3にアップグレードしました。
- Chart.js：必要な検証と互換性の更新を含め、Chart.jsを4.5.0から4.5.1にアップグレードしました。
- Less.js: Less.jsを4.2.2から4.6.4にアップグレードし、関連する検証と互換性の更新を行いました。
- Uppy：必要な検証と互換性の変更を含め、Uppyを5.0.0から5.2.0にアップグレードしました。
- jQuery UI：関連する検証と互換性の更新により、jQuery UIを1.14.1から1.14.2にアップグレードしました。
- PHP 8.5の互換性：`chr()`に関連するPHP 8.5の非推奨化の問題に対処し、関数に有効なバイト値が提供され、PHP 8.5との互換性が向上しました。
- カタログ検索：`catalogsearch_fulltext`のインデックス再作成が処理中に停止し、カタログ検索のインデックス作成の信頼性が向上する問題を修正しました。
- js-cookie: js-cookieを3.0.5から3.0.7または該当するサポートバージョンにアップグレードし、依存関係と互換性の要件に対応しました。

#### [B2B]発注がActiveMQで販売注文に自動変換されない

自動承認が有効になっているストアフロントを介して発注された発注が、ActiveMQを使用し、cron （bin/magento cron:run）を介して消費者を実行する際に、自動的に受注に変換されない問題を修正しました。 以前は、メッセージはActiveMQ キューに追加されましたが、コンシューマーがCLIを介して手動で開始されない限り処理されませんでした。 この修正により、コンシューマーはcronの実行後にメッセージを期待どおりに処理できるようになり、ActiveMQを使用するB2B マーチャントのシームレスな注文変換が保証されるようになりました。

_AC-17679_

#### Symfony L2 キャッシュの最適化と従来のキャッシュの後方互換性

Adobe Commerce 2.4.10では、既存のZend ベースのキャッシュ実装をデフォルトとして維持しながら、最適化されたSymfony L2 Cache サポートが提供されるようになりました。

Symfony Cacheを使用したいマーチャントは、明示的にそれを有効にし、Symfony L1/L2実装に固有の必要なキャッシュ設定を更新する必要があります。 Zend ベースのキャッシュを引き続き使用する既存のマーチャントは、設定を変更する必要はありません。

このデュアル・キャッシュ・アプローチにより、既存のキャッシュ構成およびデプロイメントとの下位互換性を確保しながら、要件に基づいてSymfony Cacheを柔軟に採用することができます。

### その他

#### カントリーサブ地域（州および地方）の管理者管理

加盟店は、管理インターフェイスから国のサブ地域（州や県など）を直接管理できるようになりました。 この新機能により、マーチャントは次のことが可能になります。

- 任意の国の地域を表示、追加、編集、非アクティブ化、または削除します。
- チェックアウト時、顧客の住所フォーム、管理画面の注文作成時に、新しい地域をドロップダウンオプションとして即座に利用できるようにします。コードの変更は必要ありません。
- 地域の表示名（ローカライズされた名前を含む）とISO コードを編集します。
- 既存の注文、住所、税務ルールによって参照されている地域を非アクティブ化し（履歴データが正確なままであることを確認）、そのような地域のハード削除を防ぎます。
- すべての定義済み領域は変更されず、新しいインターフェイスで表示され、管理できるようになりました。

この機能は完全に後方互換性があり、顧客対応とAPI アドレスの動作が一貫していることを保証します。
