# 複数のweb サイトや店舗

Adobe Commerce ソフトウェアの1つのインスタンスを使用すると、次のような異なる属性やコンテンツを使用する複数のweb サイトまたはストアビューを開始できます。

- デフォルト言語
- ドメイン名
- カテゴリ
- 特定可能
- 通貨

この柔軟なソリューションにより、1人のCommerce コードベースと管理者が異なるストアを管理および表示できるようになります。 Web サイト、ストアビュー、ストアビューを管理者で設定します。 バーチャルホストで特定の変数を使用して、これらのweb サイトまたはストアビューを使用してCommerce アプリケーションを起動します。

典型的な使用例は、異なるドメインに異なるオプションを持つストアを設定することです。 たとえば、あるドメインに1つのカテゴリと商品のセット、別のドメインに別の言語のカテゴリと商品のセットを持つことができます。

Commerce管理者は、web サイト、ストアビュー、ストアビューを設定します。 バーチャルホストで`MAGE_RUN_TYPE`変数と`MAGE_RUN_CODE`変数を使用して、これらのweb サイトまたはストアビューを使用してCommerce アプリケーションを起動します。

次の用語を検討します。

- **Web サイト**&#x200B;は、サイト、配信方法、支払い方法などのトップレベルのコンテナです。 カートや配送方法などを共有しない完全に個別のサイトを作成するには、個別のweb サイトを作成する必要があります。

  web サイトカスタマーアカウントは、1つのCommerceインスタンス内で複数のweb サイト間で共有できます。 Web サイトには、少なくとも1つのストアが含まれています。 カタログの価格は、web サイトのレベルで管理する必要があります。

- **Store** – はweb サイトに含まれています。 次に、ストアには少なくとも1つの&#x200B;*ストアビュー*&#x200B;が含まれています。

  複数のストアで、カート、ユーザーセッション、支払いゲートウェイなどを共有することができますが、カタログ構造とカタログ価格は分離しています。

  カタログの数量（在庫）は、店舗レベルで管理できません。 在庫は、web サイトまたはグローバルレベルでのみ管理されます。

  ストアビューは、ページの表示方法を変更します。通常、異なるレイアウトや言語でストアを表示するために使用されます。 ストアビューごとに異なる通貨を管理できます。

  各web サイトと各ストアビューには、一意のIDが必要です。 この識別子は、`MAGE_RUN_TYPE`および`MAGE_RUN_CODE`変数を次のように使用するために必要です。

- `MAGE_RUN_TYPE`は`store`または`website`のいずれかです

  - `website`を使用して、ストアフロントにweb サイトを読み込みます。
  - `store`を使用して、ストアフロントの任意のストアビューを読み込みます。

- `MAGE_RUN_CODE`は、`MAGE_RUN_TYPE`に対応する一意のweb サイトまたはストアビューコードです

次に、実行する必要があるタスクの概要を示します。

1. [管理画面でweb サイト、ストア、ストアビューを設定します。](ms-admin.md)
1. 仮想ホストを作成して、多数のweb サイトを読み込むか、Commerceのweb サイトまたはストアビューごとに1つの仮想ホストを読み込んで、各ストアに特定のディレクティブを許可します。
1. `MAGE_RUN_TYPE`と`MAGE_RUN_CODE`の値をWeb サーバーに渡します。
